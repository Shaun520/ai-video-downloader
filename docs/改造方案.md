# 改造方案（Monorepo + Next.js + Supabase + Cloudflare）

> 记录时间：2026-09-14
> 目标：把现有「Vue3 SPA + FastAPI + SQLite」改造为可上线、全免费部署的 monorepo 产品架构。

## 一、改造目标

| 维度 | 现状 | 目标 |
|------|------|------|
| 结构 | frontend / backend 两目录 | pnpm + Turborepo monorepo |
| Web 主入口 | Vue 3 SPA | **Next.js App Router + Tailwind 4**（React 重写） |
| Admin 端 | 无 | **Next.js 用户管理系统**（新） |
| 核心逻辑 | Python（yt-dlp/抖音/字幕/DeepSeek） | **TS 重写为 packages/core** |
| 认证/数据库 | PyJWT + bcrypt + SQLite | **Supabase Auth + Postgres(RLS)** |
| 部署 | 本机开发 | Vercel + Cloudflare + Supabase（全免费） |

## 二、已确认的技术决策

1. **Web 形态**：Next.js App Router（放弃 Vite，SSR/SEO 更好）
2. **核心服务**：Python 逻辑全部 **TS 重写**，进 Next.js / 容器（不保留 FastAPI，改完删除）
3. **旧前端**：营销页与功能组件全部 React 重写（markmap 思维导图库可复用）
4. **Supabase 用途**：认证 + users/orders 表 + RLS（不用 Storage 存视频文件）
5. **部署**：目标 **全免费**；Web/Admin 在 Vercel，核心在 Cloudflare，数据库在 Supabase

## 四、部署方案（全免费）

### 架构总览

```
Vercel（免费）                Supabase（免费）             Cloudflare（免费）
├─ web 前端 + SSR  ──────▶   认证 / 数据库 / RLS     ─┐
├─ admin 用户管理  ─────────▶ users / orders         │
└─ /api/* 代理转发 ───────────────────────────────▶  │
                                                     ▼
                 Cloudflare 生态（核心）
                 ├─ Containers ── core（Docker：yt-dlp + ffmpeg + Node）
                 ├─ Workers ──── /api 代理 / SSE 流式转发
                 ├─ Pages ────── 前端托管（可选，替代 Vercel）
                 └─ R2 ───────── 中间文件/缩略图（免费 10GB）
```

### 平台选择演进记录（为什么是 Cloudflare）

1. **Vercel（排除）**：页面与 SSR 完美，但 Serverless 无法承载视频下载核心——执行超时（免费 10s）、`/tmp` 易失且仅约 512MB、**无 ffmpeg**。Vercel 只保留 Web/Admin + 代理。
2. **Koyeb（排除）**：原候选，但 2026.02 被 Mistral AI 收购后转型 GPU/AI 推理（Mistral Compute），免费通用实例层正在退役，政策动荡，不可作为上线地基。
3. **Render / Zeabur（备选）**：Render 免费层稳定但 15 分钟休眠（需 GH Actions 保活）+ 免费带宽仅 5GB/月；Zeabur 国内友好但免费额度少。
4. **✅ Cloudflare Workers Containers（选定）**：
   - 任意 Docker 镜像（镜像内装 yt-dlp + ffmpeg），免费月度额度：375 vCPU-min + 25 GiB·h 内存 + 200 GB·h 磁盘 + 1TB 出口（NA/EU）
   - 无需信用卡；Anycast 全球 330+ 城市，国内访问是所有免费选项中最好的
   - 免费额度为 included 性质，超出拒服务不扣费，适合先上线验证

> 注意：经典 Workers 不行（10ms CPU、无子进程、128MB 内存），必须用 **Containers**。

## 五、关键设计原则

1. **直链优先**：下载优先返回源站直链（`direct-url`），浏览器直连下载，绕开平台带宽/易失磁盘/超时三个坑
2. **单请求内完成**：涉及中转的文件下载，一次请求内"下载 → 流式返回"，不落盘存档（免费容器磁盘易失）
3. **核心保持轻量**：核心服务只做 parse / direct-url / 字幕 / SSE 总结，适配免费额度
4. **SSE 流式**：总结/问答走 Server-Side Events，Workers 中转不中断流
5. **Supabase 替代 jwt/bcrypt**：认证完全交给 Supabase Auth，删除 auth.py / api_auth.py 自研逻辑；users/orders 表 + RLS 复刻原 database.py 的每日次数/VIP 逻辑

## 六、分阶段实施计划

| 阶段 | 内容 | 产出 | 依赖 |
|------|------|------|------|
| 1 | monorepo 骨架：pnpm workspace + turbo，apps/web、apps/admin、packages/core 空页跑通 | 可运行的工程骨架 | 无 |
| 2 | packages/core TS 重写：downloader / douyin / subtitles / summarize / sse | 纯函数核心库 | 无 |
| 3 | Supabase 接入：建 users/orders 表 + RLS；认证切换 Supabase Auth | 认证与数据层 | 用户提供 Supabase 凭据 |
| 4 | Web 端 React 重写：营销页 + dashboard + SSE 渲染 + markmap | 主入口功能完整 | 阶段 2/3 |
| 5 | Admin 端：用户管理 / 订单 / VIP 调整 | 管理后台 | 阶段 3 |
| 6 | Stripe 移植 + Dockerfile + Cloudflare/Vercel 部署 + 国内访问优化 | 上线 | 阶段 4/5 |

## 七、工作量与风险

- **最重两块**：抖音解析逆向逻辑 TS 翻译（douyin.py 逐行对照）；SSE + markmap 的 VideoSummary 组件 React 化
- **部署环境**：yt-dlp / ffmpeg 需在容器内（Cloudflare Containers 满足）；Serverless 环境（如 Vercel Functions）跑不了子进程
- **Supabase 迁移**：认证从自研 JWT 切到 Supabase；赠送额度注意用量
- 老 FastAPI 为参照基线，改造完成即整体删除，不做兼容
